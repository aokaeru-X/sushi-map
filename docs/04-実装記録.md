# 04. 実装記録

**設計を変える前に読んでください。** 「なぜこうなっているか」を残しています。理由を知らずに変えると、同じ問題を踏み直すことになります。

---

## 1. なぜビルド不要の静的サイトなのか

**結論：** フレームワークもビルドツールも使わず、HTML + CSS + 素のJavaScript + JSON だけで作りました。

**理由：**

1. **中身の寿命が長く、技術の寿命が短い。** このサイトの価値は55件の調査データにあります。5年後にReactのバージョンが上がって動かなくなるより、素のHTMLで確実に動き続けるほうが目的に合います。
2. **編集者が非エンジニアでも扱える。** データ更新は「JSONを直す」だけで完結し、ビルドもデプロイ作業も要りません。
3. **GitHub Pages にそのまま置ける。** CI/CDの設定が不要です。
4. **Leaflet を同梱（`vendor/`）したのも同じ理由。** CDNが落ちても、CDNのURLが変わっても影響を受けません。

**変えるとしたら：** データが数千件規模になり、検索が重くなったとき。その時点でも「静的サイト＋クライアント検索」の枠内で解決できないか先に検討してください。

## 2. データを1つの大きなJSONにまとめた理由

`data/calligraphy-sites.json` は260KBの単一ファイルです。項目ごとにファイルを分ける案もありましたが、まとめました。

- 55件程度なら初回ロードは一瞬で、分割による体感差はない
- ファイルが1つなら、全体検索・一括置換・差分レビューが容易
- 分割するとインデックスファイルの管理が別途必要になり、かえって壊れやすい

**変えるとしたら：** 数百件を超えたとき。カテゴリ別分割＋遅延読み込みが素直です。

## 3. 地図ピンの重なり回避（jitter）

西安には4件（大雁塔・顔真卿史跡・西安碑林・陝西歴史博物館）、洛陽周辺にも複数の項目が集中し、初期実装では**ピンが完全に重なって1つにしか見えませんでした**。

`jitteredLatLng()` で、同じ座標（小数点2桁で丸めて判定）に複数のピンが来た場合、2件目以降を螺旋状に少しずつずらしています。

```js
var angle = count * 2.4;      // 黄金角に近い値で均等に散らす
var r = 0.06 * count;         // 中心から徐々に離す
```

**注意：** これは**表示のためのずらしで、実際の座標ではありません**。詳細パネルに出す住所・座標は元の値を使っています。

## 4. APIキーをクライアントに置かない設計

台北・国立故宮博物院のOpenAPIは**APIキー認証**です。素直に実装すると `js/` からfetchすることになりますが、**これは採用しませんでした。**

**理由：** このサイトは静的サイトで、リポジトリは公開されています。クライアント側のJS/HTML/JSONにキーを書けば、**ページのソースを見るだけで誰でもキーを取得できます。**

**採用した構成：**

```
[手元のPC]                              [公開サイト]
scripts/fetch-npm-opendata.mjs
  ├ .env からキーを読む（コミットされない）
  ├ 故宮APIを叩く
  └ data/npm-collection.json を生成  ──→  ブラウザは静的JSONを読むだけ
```

これにより、キーは手元から出ません。副次的な利点として、**CORS制約を受けない**・**表示が速い**・**APIが落ちてもサイトは動く**という効果もあります。

`.gitignore` に `.env` `*.key` を登録し、実際に無視されることをコミット前に確認済みです。

**同種の外部API連携を追加する場合も、必ずこの方式を踏襲してください。**

## 5. 公開にあたっての判断

このサイトは書籍を出発点にしています。公開（public リポジトリ + GitHub Pages）にあたり、次の線引きをしました。

| 対象 | 判断 | 理由 |
| --- | --- | --- |
| 解説文（`details` など） | **掲載する** | Web調査に基づき独自に執筆したもの |
| 通し番号・カテゴリ区分 | **掲載する** | 書籍を参照するための手がかりとして必要 |
| 各項目の「参考書籍 該当ページ」 | **掲載する** | 出典を示す通常の引用表記にあたる |
| **索引項目とページ番号の対応** | **削除した** | 索引の編集そのものが書籍の成果物であり、掲載すると書籍の索引を代替してしまう |

索引からページ番号を落とした結果、**「作品名 → 書籍の何ページ」から「作品名 → それを実見できる現地の史跡」へ性格が変わり**、旅行ガイドとしてはむしろ本来の用途に近づきました（例：「蘭亭序」→ 6. 王義之故居と蘭亭）。

**今後、書籍由来のコンテンツを追加する際もこの線引きを踏襲してください。**

## 6. データ調査の経緯と、見つかった誤り

データは55件を4グループに分けて並行調査し、その後に一次資料と突き合わせて検証しました。**この検証工程で4件の重大な誤りが見つかっています。**

### 6.1 巻頭「中国全図」との照合で判明した誤り

当初は書籍の**目次だけ**を頼りに所在地を推定して調査していました。後から巻頭の「中国全図」（全55件の通し番号入り地図）を確認したところ、以下が判明しました。

| # | 誤り | 正しい内容 |
| --- | --- | --- |
| 1 | 三大石窟の番号が入れ替わっていた | 14=雲崗石窟 / 15=龍門石窟 / **16=莫高窟**（当初は14と16が逆） |
| 2 | 20と21の区切りが違っていた | 20=韓仁銘（滎陽）／21=上尊号奏・**受禅表**（臨潁県）。受禅表は上尊号奏と同じ漢献帝廟にある |
| 3 | **24 万仏堂石窟を全く別の場所と誤認** | 正しくは**遼寧省錦州市義県**（当初は河南省鞏義市の鞏県石窟寺としていた） |
| 4 | 6 王羲之故居に生地が抜けていた | 全図は臨沂（山東省・生地）と紹興の**二か所**を示していた |

**3は最も重大でした。** 遼寧の万佛堂石窟は元景造像記・韓貞造像記で知られる現存最北の北魏石窟で、河南の鞏県石窟寺とは全くの別物です。索引の「元景造像記」「韓貞造像記」が万佛堂のものであることとも整合しており、誤りが確定しました。

**教訓：**
- **目次だけから所在地を推定して調査を始めない。** 一次資料（全図・本文）で所在地を確定してから調べる
- 索引など**別の情報源との整合性**は誤り検出に有効

### 6.2 Web検証で判明した情報の更新

| 対象 | 内容 |
| --- | --- |
| 西安碑林博物館 | 2025年5月に新館全面開放、入場料が10元→**全票85元**に改定 |
| 陝西歴史博物館 | 2024年5月開館の「秦漢館」は西咸新区にある**別施設・別予約** |
| 新疆博物館 | 《李柏文書》の**原本は日本の龍谷大学蔵**。現地で見られると誤解させない記述に修正 |
| 顔真卿 | 2020年出土の《羅婉順墓誌》（38歳・728字）を追記 |
| 莫高窟 | 2025年5月公開の「数字蔵経洞」を追記 |

**教訓：** 中国の博物館は**改修・新館開館・料金改定が頻繁**です。記憶や古い情報に頼らず、必ず最新情報を確認してください。

## 9. 既知の制約・未完了事項

**引き継ぐ人へ：以下は「バグ」ではなく、意図的に残している状態です。**

| 項目 | 状況 | 対応するなら |
| --- | --- | --- |
| **索引の未収録範囲** | 元書籍の索引のうち、な行の一部・ぬ〜の行・わ行が未収録。該当ページの写真が未提供のため | 該当ページの写真を入手して `calligraphy-index.json` に追記 |
| **出典URLの疎通未確認** | 開発環境から中国・台湾のドメインへ接続できず、URLの生存確認ができていない。URLはWeb検索の結果から採取したもの | 通常のネットワーク環境で一括チェック |
| **一部座標が近似値** | 正確な地点が特定できなかった項目は市の中心座標等で代用（該当箇所は `travel.tips` 等に注記あり） | 現地訪問時や地図アプリで実測して精度を上げる |
| **故宮APIの実レスポンス未検証** | ネットワーク制限のため、模擬データでのテストのみ。APIのパス・レスポンス形式は未確定 | APIキーとエンドポイント仕様を入手し `--mode=api` で実行して調整 |
| **索引の紐づけ余地** | 211項目中187項目がリンク済み（89%）。残り24項目は該当史跡が本サイトに無い、または特定できなかったもの | 確証が得られたものから `relatedSiteId` を追加 |
| **画像を掲載していない** | 著作権上の配慮から、写真は掲載せず外部アーカイブへのリンクのみ | CC0/CC BY の画像に限れば掲載可能（出所表示が必要） |
